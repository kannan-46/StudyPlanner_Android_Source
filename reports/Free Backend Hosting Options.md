# Choose a Free Backend That Fits

For this app, **Vercel Hobby is the most practical current $0 option for a personal, non-commercial start**, because WebSocket support—including Socket.IO—became generally available in October 2026. It is not an always-running Express server: the API must fit Vercel Functions, and Hobby limits each connection to a five-minute function lifetime, so the app must reconnect. Google Cloud Run and Render also have recurring free allowances, but Cloud Run requires a billing account and has usage-based charges, while Render sleeps when idle. Railway’s current pricing does not meet strict ongoing $0 after its trial. **None of these providers promises lifetime-free hosting**; the conclusion here is about current plans checked on November 12, 2026, not a guarantee that terms will never change.

## Vercel Hobby supports Socket.IO with short-lived connections

Vercel Hobby currently costs $0 and includes **1 million function invocations, 4 active CPU hours, and 360 GB-hours of memory per month**. Vercel announced WebSocket general availability on October 20, 2026, and its launch documentation explicitly lists Socket.IO support. This updates older Vercel guidance that said functions could not host WebSockets; the later dated GA announcement is the stronger indicator of current support. ([Hobby plan](https://vercel.com/docs/plans/hobby), [WebSocket GA announcement](https://vercel.com/changelog/websocket-support-is-now-generally-available), [Socket.IO support](https://vercel.com/changelog/websocket-support-is-now-in-public-beta), [older generic limits page](https://vercel.com/docs/limits))

The main tradeoff is the serverless lifecycle. Hobby functions can run for at most **300 seconds**, and a WebSocket connection ends when its function reaches that limit. The client must reconnect; long-lived idle connections also hold provisioned memory while open. The existing API will need a Vercel Function entry point instead of relying only on a permanently running `app.listen()` process, and live-update state should be stored outside function memory. The app already reconnects its Socket.IO client, which makes this route worth testing, but a real deployment is needed to measure its connection and quota use. ([Function duration limits](https://vercel.com/docs/functions/configuring-functions/duration), [WebSocket FAQ](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections), [Function usage and pricing](https://vercel.com/docs/functions/usage-and-pricing))

Hobby is restricted to **personal, non-commercial use**. Vercel’s terms say it can change or discontinue the plan, so a future public or commercial multi-user release could require a different plan even if today’s usage stays below quota. ([Hobby plan](https://vercel.com/docs/plans/hobby), [Vercel Terms](https://vercel.com/legal/terms))

## Cloud Run keeps a normal API but requires billing controls

Cloud Run is a good alternative if preserving the existing Node server matters more than avoiding setup. It has recurring monthly no-cost quotas: request-based billing includes **180,000 vCPU-seconds, 360,000 GiB-seconds of memory, and 2 million requests**; instance-based billing includes **240,000 vCPU-seconds and 450,000 GiB-seconds of memory**. Cloud Run supports WebSockets, but each connection has a configurable timeout up to **60 minutes**, after which the client must reconnect. An open socket keeps an instance active and is billed using instance-based rates, which can consume the free allowance faster than occasional REST calls. ([Cloud Run pricing](https://cloud.google.com/run/pricing), [WebSocket guidance](https://docs.cloud.google.com/run/docs/triggering/websockets))

A normal user-managed Cloud Run project requires a linked billing account, and usage beyond quotas or separately billed build/network services can incur charges. Mumbai is an available region, but the listed 1 GiB no-cost internet-transfer allowance is scoped to North America, so don’t assume it covers traffic from an India deployment. A stable outbound IP for a narrow Atlas allowlist requires VPC routing and Cloud NAT, adding more setup and possible charges. ([Cloud Run billing requirements](https://docs.cloud.google.com/docs/starter-tier), [Cloud Run pricing](https://cloud.google.com/run/pricing), [static outbound IP](https://docs.cloud.google.com/run/docs/configuring/static-outbound-ip), [Cloud NAT pricing](https://cloud.google.com/vpc/network-pricing))

## Render is free monthly but sleeps when idle

Render currently provides **750 free instance hours per workspace each month**, resetting monthly, for free web services. Its free service has 0.1 CPU and 512 MB RAM and supports WebSockets, so it can run a small Express and Socket.IO service. It sleeps after 15 minutes without inbound HTTP or WebSocket messages, and waking it can take about a minute. Render describes free instances as suitable for hobby, testing, and preview use, not production; they can restart and have an ephemeral filesystem. For this app, that means the first API request after an idle period can be slow and an active socket can be interrupted when the instance sleeps or restarts. ([Render Free plan](https://render.com/docs/free), [compute plans](https://render.com/docs/compute-plans), [WebSockets](https://render.com/docs/websocket))

Render can connect to Atlas using its region-specific outbound IP ranges, but those ranges are shared by other services in the region; dedicated outbound IPs require a paid Pro workspace. Render’s terms also reserve the right to change services and usage limits. ([Render outbound IPs](https://render.com/docs/outbound-ip-addresses), [Render Terms](https://render.com/terms))

## Railway is convenient but not ongoing $0

Railway is technically comfortable for a conventional Express server: its public networking supports WebSockets without a fixed connection-duration limit. However, its current pricing page describes a **$5 trial credit for 30 days followed by $1 per month** on its Free card; the separate Hobby tier has a **$5 monthly minimum**. The pricing page’s “Free” label and post-trial dollar amount are confusing, but it does not qualify as strict ongoing $0. ([Railway pricing](https://railway.com/pricing), [networking limits](https://docs.railway.com/networking/public-networking/specs-and-limits))

Deno Deploy also lists a free tier, but Deno has scheduled the service to end in April 2027, so it is not a durable foundation for this app. ([Deno Deploy sunset information](https://docs.deno.com/deploy/reference/frameworks/))

## Conclusion

Start by testing the API on **Vercel Hobby** if this remains a personal, non-commercial app and the five-minute Socket.IO reconnect cycle is acceptable. Keep MongoDB Atlas credentials only on the backend; the hosting free tier does not change Atlas’s separate limits or guarantee that the database stays free. If the existing always-running server model is more important, Cloud Run is the more flexible alternative, but it is not a hard $0 cap; Render is easier to try but its sleeping behavior makes it less dependable for everyday use. Treat any current free quota as a budget opportunity, not a lifetime promise.
